`java.sql.Connection` 에 대한 예외처리를 공통화 해본다.

# 1. Wrapper class

프록시와 비슷하게 Wrapper class를 만들어 target 인스턴스의 특정 메서드를 수행할 때 전후로 처리

```java

public class DatabaseConnection {
    private final Connection connection;
    private final AbstractExceptionHandler exceptionHandler;

    public DatabaseConnection(Connection connection, AbstractExceptionHandler exceptionHandler) {
        this.connection = connection;
        this.exceptionHandler = exceptionHandler;
    }

    public ResultSet executeQuery(String query) {
        try (Statement stmt = connection.createStatement()) {
            return stmt.executeQuery(query);
        } catch (SQLException e) {
            exceptionHandler.handleException(new ApplicationException("Query execution failed", e, ExceptionLevel.ERROR));
            return null; // Or handle a default value if needed
        }
    }

    public int executeUpdate(String query) {
        try (Statement stmt = connection.createStatement()) {
            return stmt.executeUpdate(query);
        } catch (SQLException e) {
            exceptionHandler.handleException(new ApplicationException("Update execution failed", e, ExceptionLevel.CRITICAL));
            return 0; // Or handle a default value if needed
        }
    }

    // Additional methods like executePreparedStatement(), close(), etc.
}

```


# 2. 전략 패턴

각 드라이버의 예외 처리가 공통화가 어렵다면 특정 드라이버에 특화된 예외 클래스를 각각 구현해놓고 전략패턴으로 구성

```java

public abstract class AbstractExceptionHandler {
    public abstract void handleException(ApplicationException e);

    public static AbstractExceptionHandler getHandler(String driverName) {
        return switch (driverName) {
            case "com.mysql.cj.jdbc.Driver" -> new MySQLExceptionHandler();
            case "oracle.jdbc.OracleDriver" -> new OracleExceptionHandler();
            // Other cases for different drivers
            default -> new GenericExceptionHandler();
        };
    }
}

```


# 3. Java 동적 프록시 `InvocationHandler`

자바에서 제공하는 프록시 패턴을 구현한다.

```java

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;
import java.sql.Connection;

public class ConnectionProxy implements InvocationHandler {
    private final Connection connection;
    private final AbstractExceptionHandler exceptionHandler;

    public ConnectionProxy(Connection connection, AbstractExceptionHandler exceptionHandler) {
        this.connection = connection;
        this.exceptionHandler = exceptionHandler;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        try {
            return method.invoke(connection, args);
        } catch (Exception e) {
            if (e.getCause() instanceof SQLException) {
                exceptionHandler.handleException(
                    new ApplicationException("Database error in method " + method.getName(), e.getCause(), ExceptionLevel.ERROR)
                );
            }
            throw e;
        }
    }

    public static Connection createProxy(Connection realConnection, AbstractExceptionHandler handler) {
        return (Connection) Proxy.newProxyInstance(
            realConnection.getClass().getClassLoader(),
            new Class<?>[] { Connection.class },
            new ConnectionProxy(realConnection, handler)
        );
    }
}

```


# 4.  `Thread.setDefaultUncaughtExceptionHandler(UncaughtExceptionHandler eh)`  

JVM 내 모든 스레드에서 발생하는 예외에 대해서 예외 방식을 설정한다. 말 그대로 모든 스레드이기 때문에 백그라운드에서 동작하고 있는 스레드의 예외가 발생했을 때도 fallback 함수를 통해 예외 처리를 할 수가 있다.

예외 처리를 중앙화할 수 있지만 기존에 설정해놓은 예외를 대체하여 특정 예외 처리 로직을 수행하지 못할 수도 있다.  따라서 적용할 스코프를 적당히 조절할 필요가 있다고 한다. 웹에서는 `@ControllerAdvice`나 AOP를 많이 사용했어서 잘 모르는 처리 방법이다. 

```java

public class MyApp {
    
    public void start(Stage primaryStage) {
        // Set up global uncaught exception handler
        Thread.setDefaultUncaughtExceptionHandler((thread, throwable) -> {
            if (throwable instanceof ApplicationException) {
                logException((ApplicationException) throwable);
                showAlert((ApplicationException) throwable);  // Optional for critical errors in UI
            } else if (throwable instanceof SQLException) {
                logException(new ApplicationException("SQL error", throwable, ExceptionLevel.CRITICAL));
                handleCriticalFailure();
            } else {
                // Log or handle other types of exceptions
                logGenericException(throwable);
            }
        });

        primaryStage.show();
    }

    private void logException(ApplicationException e) {
        // Implement logging logic here
        System.err.println("Logging exception: " + e.getMessage());
    }

    private void showAlert(ApplicationException e) {
        Platform.runLater(() -> {
            Alert alert = new Alert(Alert.AlertType.ERROR, e.getMessage());
            alert.showAndWait();
        });
    }

    private void handleCriticalFailure() {
        // Handle clean-up or emergency shutdown if needed
    }
}

```
