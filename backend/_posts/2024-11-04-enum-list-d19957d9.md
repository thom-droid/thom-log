유저는 여러 권한을 가질 수 있다. 권한은 enum 으로 처리하는데, 애플리케이션에서는 리스트로, db에서는 콤마로 구분된 문자열로 관리하려고 한다.

# 1. TableCollection
- 테이블을 새로 생성하여 1:N 형태로 구성하는 방식이다.

### 1. Main Table (`business`)

Assuming that the main table, `business`, has columns like `id`, `name`, and other attributes, it would look something like this:

|id|name|other_columns|
|---|---|---|
|1|Company A|...|
|2|Company B|...|

### 2. Secondary Table (`business_status`)

The `business_status` table holds each status as a separate row, with a foreign key to `business.id`. This structure supports a one-to-many relationship between `business` and `status`.

|business_id|status|
|---|---|
|1|ACTIVE|
|1|INACTIVE|
|1|PENDING|
|2|ACTIVE|


# 2. @Convert 사용

- 커스텀한 컨버터를 만들어 리스트인 경우 엘리먼트를 문자열로 만들고, 문자열인 경우 리스트로 만들도록 컨버터를 설정한다. 
- ``AttritubeConverter`` 를 구현하여 정의한다.
